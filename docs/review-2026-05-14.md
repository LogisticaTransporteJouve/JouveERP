## 1. Lo que está hecho

**Fases A–F shippeadas, 40 PRs mergeados desde repo vacío.** Toda la mitad de
AR/facturación del ERP, end-to-end.

**Superficie shippeada:**

- **Auth + RBAC** (`lib/auth/`): 6 roles, ~45 permisos, matriz `userCan` con
  100% de cobertura Vitest, escalera de privilegios `canAssignRole`, trigger
  SQL "owner mínimo", `audit_events` con inserts solo desde service role,
  `bootstrapOwnerIfNeeded` one-shot.
- **Clientes** (`features/clients/`): modelo global por CUIT único,
  `verifyCuit` AFIP con cache + rate-limit + fallback stale, búsqueda fuzzy
  `pg_trgm` vía RPC `search_clients`, saldos iniciales, tab de cuenta
  corriente con vista `v_client_account_movements`.
- **AFIP plumbing** (`lib/afip/`): WSAA con subprocess OpenSSL CMS, cache TA
  single-flight, SOAP manual + `fast-xml-parser` (sin la lib `soap` enorme),
  `wsfev1` con orden estricto de campos, jerarquía de errores tipada
  (`AfipTransport/Soap/Service/Config/Input`), página de diagnostics, sync de
  `puntos_de_venta`.
- **Facturación** (`features/invoices/` + `lib/inngest/functions/issue-invoice.ts`):
  workflow durable e idempotente con
  `reserve→persist→requestCAE→recovery vía FECompConsultar→persist→PDF`,
  fiscal+interno en una sola tabla, NC/ND con `cbtesAsoc`, modo rápido
  "Emitir y continuar", smoke E2E AFIP gateado por `RUN_AFIP_E2E=1`.
- **Caja** (`features/accounts/`, `features/transactions/`): caja única con
  transactions etiquetadas por canal, RPC atómico `create_transfer` con
  cross-pointer, opening balances, vista `v_transactions_tagged` para reportes.
- **Recibos / Cheques / Retenciones / Aging** (`features/receipts/`,
  `features/checks/`, `features/aging/`): numerador `R{POS}-{numero}`,
  payment_lines con auto-creación de metadata de cheque, allocations con
  sum-validation, soft-cancel, auto-link recibo→transaction, RPCs de
  lifecycle de cheques (`deposit/credit/endorse/reject`), vistas
  `v_aging_documents` + `v_client_aging` con buckets, cron semanal.
- **Realtime** (`hooks/use-realtime-invalidate.ts`): un solo hook genérico
  cableado en 6 tablas, respetando RLS, con las tablas hijas piggybackeando
  intencionalmente sobre el `updated_at` del padre.
- **Patrón de queries**: RSC prefetch + `useSuspenseQuery` en todas las
  features, `loading.tsx` por ruta, `(dashboard)/error.tsx` global, sin más
  `revalidatePath`.
- **Seguridad**: CSP con nonce per-request en `proxy.ts`, destructive
  monocromo (sin rojo), `server-only` en el service client, ESLint banea
  `any`, CI de types drift, CI de orden de migraciones.
- **Documentación**: `roadmap.md` es modelo de decision-log;
  `sumary-frontend-patterns.md` y `ai-patterns.md` son nivel referencia.

## 2. Cosas raras encontradas

### 🔴 Crítico — entorno local roto

`pnpm install` está **desfasado** respecto al lockfile. A `node_modules/` le
faltan `@react-pdf/renderer`, `@sentry/nextjs`, `@playwright/test`, `qrcode`,
`fast-xml-parser` — todos listados en `package.json`. Síntomas:

- `pnpm typecheck` → falla con 16+ errores TS2307
  (`Cannot find module '@sentry/nextjs'`, etc.).
- `pnpm test` → 4 suites no cargan (`lib/afip/qr.test.ts`,
  `lib/afip/padron.test.ts`, `lib/afip/wsfev1.test.ts`,
  `scripts/preview-pdf.test.tsx`). 90 tests igual pasan.
- CI verde porque GH Actions hace `pnpm install --frozen-lockfile` fresco.

**Fix: correr `pnpm install`.** Pasó cuando se actualizó el lockfile en el
commit `b2a2e8d` (14 mayo) sin re-instalar local.

### 🟡 Deuda "tooling instalado pero sin configurar" del roadmap

El roadmap §A.2 lista esto como ⏳ pendiente y sigue así:

- **No hay `.prettierrc` / `.prettierignore`**. `pnpm format:check` no está
  en CI por eso. Decidir: `semi: true` (matchea el código) o `false`
  (matchea defaults de shadcn).
- **Husky hooks no escritos**. `.husky/_/` existe con stubs, pero faltan
  `.husky/pre-commit` y `.husky/pre-push` — así que `lint-staged` y el
  check pre-push de types drift no se disparan local. Hoy solo CI atrapa
  el drift.
- **`lint-staged.config.mjs`** no está.

Son fixes de 30 minutos que el roadmap explícitamente trackea. Vale la pena
cerrarlos antes de arrancar Fase G.

### 🟡 `claude-proxy/` viola la decisión #8

Roadmap §8 flaggea un POC untracked de Express + `ExtractorFactura.jsx`
afuera del repo. La decisión #8 dice "todo en Next.js + Inngest, sin
servicios extra". Opciones:

- Migrar la lógica de OCR a un server action + función Inngest de Fase I.2
  (`features/ocr/` + `lib/inngest/functions/extract-invoice.ts`), o
- Borrar el POC y dejar documentados los prompts ya validados.

Dejarlo untracked indefinidamente es lo peor de los dos mundos.

### 🟡 TODO del email de aging

`lib/inngest/functions/aging-weekly-summary.ts:7,91` — el cron corre semanal
y loggea el digest, pero no hay provider de email cableado. Camino más
barato: Resend (nativo a Vercel, SDK de Node simple, sandbox de dev). PR de
~50 LOC. Mientras siga siendo solo logging, el cron tiene cero valor de
negocio.

### 🟡 Rollout de `useActionQuery` incompleto

El roadmap §F.3 introdujo `hooks/use-action-query.ts` y dice "**Refactor
pendiente** para portar el resto de los efectos". El archivo no aparece en
`hooks/` — parece que aterrizó en otro lado o se revirtió. `grep` y o
terminar el rollout o borrar el stub.

### 🟡 Escape hatches de tipos acumulándose

29 ocurrencias de `any|as unknown` en `features/`; varios `as never` sobre
`audit_events.payload` (columna Json) y `afip_observaciones`. Todos atajan
la misma raíz: los tipos generados de Supabase mapean `Json` como `Json`
pero el código inserta formas `Record<string, unknown>`. Un helper chico
`lib/db/json.ts` (`toJson<T extends object>(x: T): Json`) elimina la mitad.

## 3. El gap real del producto

**Transporte Jouve es una empresa de transporte. No hay código de
flota/viajes.**

- Fases shippeadas: A, B, C, D, E, F = clientes, facturación, caja,
  recibos, retenciones, AR.
- Fases pendientes: **G (Flota), H (Pallets), I (IA), J (Hardening).**

`features/` tiene 9 módulos — todos AR/facturación. El core de logística
(choferes, vehículos, viajes, combustible, mantenimiento, vencimientos doc,
rentabilidad) está sin arrancar. El roadmap correctamente identifica G como
siguiente ("mayor valor para Transporte Jouve, hoy es la pata sin sistema")
pero G–J siguen siendo one-liners
(`G.1 choferes + vehiculos · G.2 viajes...`).

**Próximo movimiento más impactante**, no más pulido de facturación. AR
está 80% terminado; transporte está 0%.

arquitectura es sólida (workflows durables, RLS-first, idempotencia, audit,
design system monocromo, RSC + suspense + realtime), el decision log es

Las dos cosas que lo separan de estar "shippeado":

- **Local dev roto** (fix de 5 min: `pnpm install`).
- **La mitad de transporte/logística del producto no existe todavía**
  (Fases G–H — meses de laburo).

**Un solo movimiento para la próxima semana:** dejar de pulir AR, expandir
el roadmap de Fase G al nivel de detalle de E, y arrancar `feat: drivers +
vehicles + document expiries (G.1)`. El pipeline de facturación ya está

pipeline de transporte es el valor único real.
