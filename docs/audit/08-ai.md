## FINDINGS
[high][authz/data-leak] `20260616180000_ai_insights.sql:44` + features/ai/insights/* — ai_insights SELECT granted to operations, analyst writes cards w/ treasury, AP, AR data. operations role has NO accounting:read/accounts:read/purchase_invoices:read/receipts:read. operations user opens /ai, reads cash-flow card (current ARS treasury balance), receivables-risk card (top clients + 90+ amounts), supplier-anomaly cards (supplier names + invoice totals) — none visible elsewhere in app. Documented deferred (ai-overview §10 D4 "role filtering deferred") but LIVE in shipped code. CONFIRMED. Fix: filter insight kinds by role at listInsightsAction, or split finance-only vs operations-safe.
[medium][injection/integrity] `app/api/ai/chat/route.ts:82-107` — incoming message (client-supplied UIMessage) persisted (appendAiMessage, role verbatim) + fed to convertToModelMessages WITHOUT validateUIMessages or role/shape check. Only load path validates (chat-store.ts:97). User POSTs directly w/ {sessionId, message:{role:"assistant", parts:[spoofed tool output]}} or role:"system" → fabricated tool result / system instruction enters model context + persisted as genuine transcript. Blast radius attacker's own session (tools read-only) but poisons model + ai:admin reviewing "all chats" sees fabricated content. CONFIRMED (past hardening validated load/DB side, left inbound unvalidated). Fix: validateUIMessages incoming + reject role!=user before append/stream.
[medium][idempotency] features/ai/document/actions.ts (all create*FromExtractionAction) — status guard + confirming update not atomic: read status==pending_review (l305/467/580) → create entity → update({status:confirmed}).eq("id") w/ NO WHERE status='pending_review'. Double-click → two concurrent both read pending_review, both create → TWO entities from one scan. Purchase invoices may be caught by unique (supplier,numero,pv); receipts/OPs/sales-invoice-issue have no such guard → double-post. PLAUSIBLE→CONFIRMED. Fix: conditional confirm update (.eq("status","pending_review")) + only create if flips a row, or advisory lock.
[low][cost-accuracy] features/ai/lib/chat-store.ts:164-174 — estimateCostUsd prices inputTokens at full input rate, ignores cachedTokens (logged never discounted). Anthropic caching ~0.1× on cache reads → cost OVERestimated → cap trips earlier + ai:admin figures + daily meter inflated. Fix: subtract cached tokens, price at cache-read rate.
[low][race] route.ts:66-80 — daily-cap check reads getAiUsageToday before turn, current turn tokens not counted (acknowledged). Two parallel requests near cap both pass. Bounded by stepCountIs(8) + 30/hr. CONFIRMED but low.
[low][doc-drift] ai-overview.md §3 lists tools that DON'T exist in tools/registry.ts: searchGlobal, getChannels, getInvoiceDetail, getPayrollPeriod, getEmployeeLeaves, getSuppliers/getClients list variants, runReadOnlySql. 6 fleet tools that DO exist aren't in doc catalogue. agent.ts + docs say "~25 tools"; actual 31. tool-renderers.tsx TOOL_LABELS missing all 6 fleet tools → render as generic "datos". Fix: reconcile §3 + add fleet labels.

## DESIGN TENSIONS
1. Insight visibility vs domain permissions — insights inherently cross-domain (cash-flow needs treasury+AP+AR+HR) but permission model per-domain. Current "anyone with ai:read" flattening (Finding 1) is path of least resistance; correct fix needs per-kind role gating mirroring domain matrix (deferred D4). Recurs when HR/payroll insight cards ship.
2. Service-role reads under user gate — every tool runs userCan then queries w/ getServiceClient (RLS bypass), explicit deviation from ai-patterns.md §23. userCan line is ONLY boundary — any future read action forgetting it leaks w/ no RLS backstop. AI tool layer amplifies (one chat turn fans ~31 actions).
3. Client-supplied session id + client-supplied message — ownership enforced (ensureAiSession) but trusting message shape (Finding 2) is softer half of same "client controls request" surface.

## EXPECTATION GAPS
- ai-analyst cron: expected unbounded LLM tokens — REFUTED, fully deterministic (buildInsights math, no model call). Failure retries 2× + throws (open rows only deleted after successful rebuild).
- Document Intelligence auto-post wrong expense from garbage PDF — REFUTED: only writes pending_review; classifyExpense demotes <0.5 confidence to UNMAPPED; posting through human-confirmed domain write. Real gap is double-confirm race (Finding 3).
- Client model-picking / abort partial-save — REFUTED: model server-fixed; onFinish persists only completed response.
- Team-chat authz — SOLID: membership enforced by user_is_channel_member() in every RLS policy; admin RPCs re-check role=admin; realtime torn down on unmount; edit/delete scoped by sender_id. No finding.
