PDF regenerated on demand; SHA-256 pdf_hash persisted at emission, never re-verified at serve.
Invariants: fiscal fields→trigger check_invoice_fiscal_fields; numbering unique index; header immutability post-emitted→trigger; fiscal emitted→cancelled blocked→trigger; no DELETE emitted→trigger; NC/ND require origin→CHECK; internal numbering race-free→RPC; libro IVA ventas filters is_fiscal AND emitted; journal skips internal.

## DESIGN TENSIONS
1. AFIP-as-sequence vs memoized durable steps. FECompUltimoAutorizado+1 gapless but Inngest memoization freezes reserved number across retries — correct happy path, brittle for any rejection (1,15). Local per-POS reservation table + reconcile inverts tradeoff.
2. On-demand PDF + hash-only integrity assumes template stability + data immutability; items mutable (6), hash never checked at serve — proof exists, nothing consumes it.
3. One invoices table for fiscal/internal/CAE/CAEA — fiscality rules scattered across triggers/action/workflow branches; computeTotals(...,true) and null-IVA-line hole are symptoms of no single owner of "valid fiscal row".

- Internal cancellation: documented rule (internal→status='cancelled' OK) has DB support but NO server action or UI — sanctioned path unreachable in-product.
