# AUDIT — HR (agent audit-hr)

## SYSTEM MAP
Tables: employees (base_salary/cuil/cbu; soft-delete=termination_date+is_active=false); payroll_periods/entries/entry_extras (draft→closed, immutability trigger blocks entry/extra writes on closed; reopen allowed by trigger, gated hr:admin in action only); payroll_payments (trigger keeps 1:1 transactions row; no immutability — payments on closed intended); employee_leaves (days=generated end-start+1); employee_vacation_balances (UNIQUE employee,period_year; saldo=entitled+bonus+carryover−used); hr_settings; attendance_records (exception model, UNIQUE employee,date); holidays; employee_documents (append-only, notified_at cooldown).
Views: v_payroll_entries_resolved, v_payroll_entries_with_payments, v_employee_vacation_balances, v_attendance_records_resolved — all WITHOUT security_invoker; v_documents_expiring — with it.
Crons: vacation-balances-grant (Oct 1 → grant_vacation_balances(year,true), idempotent); document-expiry-alerts (daily 08:00 ART, ≤30d, 7d cooldown, fan-out owner/admin/finance).
RBAC hr:read/write=owner/admin/finance, hr:admin=owner/admin. Actions use USER-scoped client (RLS live). used_days maintained by trigger sync_vacation_balance_used → apply_vacation_delta (FIFO consume/LIFO refund over active|extended).

## DESIGN TENSIONS
1. Action-layer RBAC vs DB-layer RLS granularity — hr:admin only in TS; RLS knows owner/admin/finance. Two bypasses (payroll reopen by finance, grant RPC by anyone).
2. Carryover vs expiry — balances expire Apr-30 yet remainder resurrects Oct-1; expired state cosmetic 5 months/yr. Model wants true expiry or rolling balance.
3. Exception-based attendance vs derived "días trabajados" — doc promises derivation but nothing computes it; holiday_sync trigger missing; active-only lists make historical months unreliable. Half a design.

## EXPECTATION GAPS
- No vacation request/approval workflow (leaves are admin-recorded facts; cancel=hard delete, restore=broken trigger refund). Negative balances accepted, no alert.
- Nothing happens on termination beyond employee row: active balances stay active, future leaves keep consuming, docs stop alerting only via is_active view filter.
- No grant-on-hire → anyone hired after Oct 1 has no balance until next Oct 1 (feeds silent-consumption bug).
- docs/hr-patterns.md otherwise accurate; confirmed drifts: vacation_carryover config claim, getServiceClient claim §8, "sin select *", silence on 4 non-invoker views.
